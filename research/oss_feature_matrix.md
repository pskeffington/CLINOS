## Reproducibility and limitations

- Evidence commands: `gh api repos/<owner>/<repo>` for default branch, last push, GitHub license metadata; `gh api repos/<owner>/<repo>/releases/latest`; `gh api repos/<owner>/<repo>/commits/HEAD`; direct inspection of public README/license/source docs. All were read-only.
- Exact commit/release snapshots and license observations are also recorded in `research/literature_matrix.csv` (SRC-005 through SRC-012 and SRC-019). License links in this matrix are pinned to the audited commit.
- GitHub API `NOASSERTION` is reported for OpenMRS core and its FHIR2 module. The pinned LICENSE files for both state MPL-2.0 and include a Healthcare Disclaimer; code-level notices and module rights need legal/reviewer validation before reuse.
- The date reflects a point-in-time repository snapshot. Maintenance activity, versions, branches, release assets, dependencies, licenses and hosted offerings can change; refresh before integration.
- This was not a clone/build/test/security audit of candidate projects; no source was copied, no real data was fetched, and no external endpoint was called.
- License identifiers are repository metadata, not a legal conclusion or a complete transitive-dependency/SBOM assessment.
